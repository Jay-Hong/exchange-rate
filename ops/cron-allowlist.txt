# FXi가 관리하지 않는 host cron 줄의 **선언 목록**.
#
# 왜 필요한가: 배포 preflight가 "docker를 실행하는 줄"을 substring으로 골라내던 동안,
# 수집 자체를 회피하는 형태가 통과했다(실측: `docker  compose` 공백 2개 / `docker-compose`).
# 무엇을 고르든 그 밖의 표기가 남기 때문이다. 그래서 **고르지 않는다** — 모든 비주석 crontab 줄은
# `ops/cron-job.sh --print-crontab`의 정본이거나 이 파일에 **정확히** 선언돼 있어야 한다.
# 선언되지 않은 줄이 하나라도 있으면 배포가 거부한다(그 줄이 lock 밖에서 docker를 돌릴 수 있다).
#
# 형식: 주석(#)과 빈 줄을 제외한 각 줄이 crontab 줄과 **문자열로 동일**해야 한다.
# 새 host cron을 추가하면 여기에도 추가할 것. 그 마찰이 이 파일의 목적이다.
#
# ⛔ **"모든 줄 선언 = 추정 0"은 과대주장이었다 — 철회한다.** 선언되는 것은 crontab의
#    **문자열**뿐이다. 아래처럼 저장소 밖 스크립트를 가리키는 줄은, 그 스크립트 본문이
#    나중에 docker를 실행하도록 바뀌어도 crontab 문자열이 같아 preflight를 통과한다.
#    즉 이 파일은 **검증이 아니라 신뢰의 선언**이다.
#    닫는 방법은 둘뿐이다: (a) 그 스크립트를 저장소로 옮겨 관리·검증하거나
#    (b) 모든 운영 cron을 `ops/cron-job.sh` launcher 아래로 넣는다. 둘 다 별도 슬라이스다.
#    ⚠️ 해시 기록 방식도 검토했으나 기각했다 — 어느 줄이 어떤 외부 파일에 의존하는지를
#      도구가 알려면 다시 **추정**이 필요하고, 선언을 빠뜨린 의존은 여전히 안 보인다.

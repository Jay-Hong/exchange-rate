# C1b D1 탐지 정책 v1

작성: Codex / 2026-09-21  
상태: 구현을 위한 규범 명세. 구현·변이 배터리 통과·반입 승인을 뜻하지 않는다.  
기준: **beautifulsoup4 4.14.3 / `html.parser`**. 실측 환경은 CPython 3.13.5, Unicode 데이터 15.1.0이다.

## 0. 효력과 유지하는 합의

이 문서는 `d1_design_v2.md`와 `d1_design_v3_delta.md`의 탐지·결합·출현 식별에 관한 열린 부분을 확정한다.

다음 합의는 유지한다.

- 법인 공시값 보존 / 자연인 성명 제거.
- 캡처의 치환 → 저장 전 검사 → A층 탐지 → 사람 검토 → 건별 승인 기록 → 반입.
- 저장 전에는 **이번 실행에서 성공한 치환의 정확한 위치로 대응되는 탐지만** 허용한다.
- 자리표시자는 `[성명삭제]`. 원래부터 있던 자리표시자는 치환 성공의 증거가 아니다.
- 치환 지원은 검토된 공시 영역의 정확한 라벨·유일한 값 경계를 가진, 자식 태그 없이 일반 텍스트 노드 하나인 `li`로 한정한다.
- 삭제 대상으로 확정한 성명이 원본 `recorded_extraction` 문자열에 남으면 양쪽 기록을 고쳐 맞추지 않고 거부한다.
- 승인 파일 위치·닫힌 schema·두 최종 파일 SHA-256·정책 digest 결속을 유지한다. 캡처 도구는 승인 파일을 읽거나 쓰지 않는다.
- 승인 판단은 “성명 값이 삭제됨” / “자연인 성명 문맥이 아님” 둘뿐이다.
- D2의 `rrn_shape`·`card_shape`와 기존 식별자 검사는 변경하지 않는다. 아래 정규화·결합을 D2에 적용하지 않는다.

D1은 **직함 문맥 후보 탐지기**다. 성명 인식기나 익명성 증명기가 아니다.

이 문서에서 fail-closed는 **정의한 실패 상태에서 진행을 거부한다는 뜻으로만** 사용한다. 지원하는 HTML에서 모든 자연인 성명을 탐지한다는 의미로 사용하지 않는다.

## 1. 검사 입력과 결과

### 1.1 검사하는 상태

저장 전 검사는 기존 정제와 좁은 치환이 끝난 soup에서 수행하고, **실제로 저장할 UTF-8 바이트를 다시 파싱한 결과에서도** 수행한다.

기존 정제에서 제거된 속성·주석이나 비워진 script 내용은 저장 후보에 없으므로 검사 입력이 아니다. 저장 후보에 남은 요소는 보호 영역 안팎·숨김 여부·추출에 사용됐는지와 무관하게 검사한다.

A층은 저장 파일을 정제하거나 치환하지 않고 그대로 파싱한다. 기존 schema·구조·해시·식별자/D2 검사를 유지하고, D1 구조 검사·탐지·승인 대조를 추가한다.

### 1.2 검사 출처

| 출처 | 단위 |
| --- | --- |
| HTML 텍스트 | 블록 소유 run 및 그 안의 개별 텍스트 노드 |
| HTML 속성 | 각 속성 이름, 각 문자열 값 또는 목록의 각 문자열 원소 |
| Metadata | 닫힌 schema를 통과한 객체 안의 모든 문자열 값 leaf |
| 승인 파일 | D1 입력에서 제외하고 별도 제어 데이터로 검증 |

속성끼리, 속성과 본문, 서로 다른 metadata 필드를 이어 붙이지 않는다.

Metadata 객체 키는 닫힌 schema로 검증한다. 값 텍스트에 키를 이어 붙이지 않는다. D1에는 해시·enum·출처 필드라는 이유만으로 문자열 leaf 전체를 면제하는 규칙을 추가하지 않는다.

태그 이름은 §2의 유한 목록으로 검증한다. 허용 태그 이름 자체는 직함 목록과 겹치지 않으므로 별도 직함 출현으로 만들지 않는다.

**이유:** 본문과 기록·속성은 별도 잔존 경로다. 같은 문자열이라는 이유로 한 출처의 승인이 다른 출처를 덮으면 안 된다.

**한계:** Metadata 문자열 안의 HTML·JSON·URL 인코딩을 재귀적으로 해석하지 않는다.

### 1.3 결과 구분

1. **검사 불가:** 미지원 구조·노드 타입·정규화 대응 실패·환경 불일치·예외·시간 초과. 0건으로 반환하지 않는다.
2. **검사 완료, 후보 목록:** 빈 목록일 수 있다. 저장 전에는 실행 내 치환 대응을, A층에서는 건별 승인을 적용한다.
3. **승인 완료:** A층이 후보 목록과 승인 기록을 정확히 대조한 결과다.

검사 불가를 “자연인 성명 문맥이 아님”이라는 판단으로 해제하지 않는다.

진단에는 정책 소유 오류 코드와 구조 위치만 기록한다. 원문 성명·주변 문장·HTML 조각은 복사하지 않는다. 아래 오류명은 명세의 식별자이며 현재 구현돼 있다는 주장이 아니다.

## 2. 요소 3분류와 ruby

### 2.1 실제 목록

분류 기준은 bs4가 파싱한 `tag.name`이다. CSS의 `display`, class/id, 공시 영역 여부로 분류를 바꾸지 않는다.

**I — 인라인 집합:**

```text
a abbr b bdi bdo big br cite code del dfn em font i img ins
kbd label mark q s samp small span strike strong sub sup time
tt u var wbr
```

**B — 블록/분리 집합:**

```text
address article aside blockquote body button caption center col
colgroup dd details dialog dir div dl dt fieldset figcaption
figure footer form h1 h2 h3 h4 h5 h6 head header hgroup hr html
input legend li link main menu meta nav noscript ol optgroup
option p pre script section select style summary table tbody
td template textarea tfoot th thead title tr ul
```

**U — I에도 B에도 속하지 않는 모든 요소:**

무조건 미지원이다. 예:

```text
ruby rb rt rtc rp x-part svg math iframe object canvas
audio video marquee
```

U의 예시 목록은 전부가 아니다. **U는 I와 B의 합집합의 여집합**이다.

빈 U도 전체 검사를 `d1_unsupported_element`로 거부한다. U를 블록이나 투명 인라인으로 추정하지 않는다. 자식에 직함이 있는지에 따라 거부 여부를 바꾸지 않는다.

B는 웹 표준의 시각적 블록 목록이 아니라 **이 정책에서 run을 끊는 목록**이다. `button`·`input`·`option`·`meta`도 이 의미로 분류한다.

### 2.2 특수 규칙

- `label`·`ins`·`del`은 **I에 포함**한다. `del` 텍스트도 검사한다. 삭제 표시는 바이트 삭제가 아니다.
- I 안에서 B를 만나도 B 경계를 적용한다. `ins` 안의 `div`를 건너 이어 붙이지 않는다.
- `br`은 LF 한 글자, `wbr`은 문자 0개다.
- `img`는 본문 문자 0개이며 남은 속성은 별도 검사한다.
- `br wbr img hr col input link meta`는 파싱 결과 자식이 없어야 한다. 자식이 있으면 `d1_invalid_empty_element`로 거부한다.
- `script style noscript template`는 기존 정제 결과로 **`contents`가 완전히 빈 경우만** 허용한다. 공백 텍스트도 자식이다. 자식이 남으면 `d1_nonempty_inert_element`로 거부한다.
- 검사 중 내용을 지워 통과시키지 않는다.
- 빈 B도 진입·복귀 경계를 만든다.
- 텍스트는 정확히 일반 `NavigableString` 타입인 경우만 지원한다.
- `Comment`, `Doctype`, `ProcessingInstruction`, `Declaration`, `CData`, `Script`, `Stylesheet`, `TemplateString`, `RubyTextString`, `RubyParenthesisString` 등 다른 타입이 저장 후보에 남으면 `d1_unsupported_text_kind`로 거부한다.
- 모든 descendants를 순회해 분류한다. `get_text()`가 생략한 노드를 조용히 제외하지 않는다.

기존 D2의 `isinstance(NavigableString)` 기반 검사는 그대로 유지한다.

**이유:** 알 수 없는 구조를 조용히 제외하는 경로를 닫고, 기존 정제가 남길 수 있는 빈 구조 껍데기는 표현한다.

**한계:** 무해한 미지원 요소도 거부하므로 캡처 성공률이 낮아질 수 있다. 목록 확장은 정책 변경이다. 이미지 내용·CSS 생성 텍스트·실행된 script·시각적 읽기 순서는 검사하지 않는다.

### 2.3 Ruby 결정: 전부 미지원

첫 버전에서 `ruby rb rt rtc rp`는 모두 U다. 고아 `rt`·`rp`, 빈 ruby, 주석 없는 ruby도 예외를 두지 않는다.

본문/주석 투영을 지원하지 않는 이유:

1. `get_text()`는 `rt`의 `RubyTextString`을 생략한다.
2. 모든 문자열을 일렬로 붙이면 본문 중간에 주석이 끼어 직함이 사라질 수 있다.
3. 주석 자체가 여러 태그로 나뉘면 노드별 검사만으로 충분하지 않다.
4. 첫 슬라이스에서 ruby의 교차·중첩·독립 읽기 규칙까지 추가하는 대신 지원 경계를 명확히 한다.

**알면서 남기는 한계:** 무해한 ruby도 캡처할 수 없다. 이는 지원 거부 비용이며 ruby를 안전하게 검사했다는 주장이 아니다.

## 3. 블록 소유 run

### 3.1 루트와 경로

문서 루트 `BeautifulSoup([document])`를 경로 `[]`의 **가상 B**로 취급한다. fragment에 `html`·`body`를 인위적으로 추가하지 않는다.

DOM 경로는 각 부모의 `contents`에서 차지하는 **0 기반 자식 인덱스 배열**이다. 태그뿐 아니라 텍스트도 인덱스에 포함한다. 기존 `element_path`나 descendants 전역 번호와 혼용하지 않는다.

각 텍스트 노드와 `br/wbr/img` 이벤트는 **가장 가까운 B 조상**이 소유한다. 없으면 가상 루트가 소유한다. 인라인 조상은 소유자가 되지 않는다.

### 3.2 순회·방출 규칙

DOM 순서로 깊이 우선 순회한다.

1. 일반 텍스트를 원문 그대로 현재 소유자의 버퍼에 추가한다. strip이나 구분자 삽입을 하지 않는다.
2. I는 소유자를 바꾸지 않고 순회한다. 특수 요소의 문자 규칙만 적용한다.
3. 자식 B **진입 직전**, 부모 버퍼가 비어 있지 않으면 한 번 방출하고 비운다.
4. 자식 B는 별도 소유자·빈 버퍼로 시작한다.
5. 자식 B 끝에서 자식 버퍼를 방출한다.
6. 부모로 **복귀한 뒤**, 부모는 빈 새 버퍼로 이어간다. 진입 전 버퍼와 합치지 않는다.
7. B 또는 루트의 끝에서도 남은 버퍼를 한 번 방출한다.
8. 빈 문자열 run은 방출하지 않는다. 공백만 있는 run은 방출한다.
9. U나 미지원 노드는 전체 검사 거부다. 건너뛰는 복구를 하지 않는다.

Run 식별자:

```text
(owner_path, segment_index)
```

`segment_index`는 그 소유자가 실제 방출한 비어 있지 않은 run의 **0 기반 번호**다. 자식 소유자의 방출은 부모 번호를 증가시키지 않는다.

불변식:

- 비어 있지 않은 모든 지원 텍스트 노드는 정확히 한 run에만 속한다.
- 길이 0인 텍스트 노드는 독자적인 run을 만들지 않는다.
- 각 br의 LF는 정확히 한 run에 한 번 들어간다.
- 부모 run에는 자식 B의 텍스트가 들어가지 않는다.
- 인라인 내부 B·빈 B·fragment에도 같은 규칙을 적용한다.
- “자식 블록이 없는 블록만 검사”하지 않는다.
- 조상마다 `get_text()`를 호출해 같은 내용을 다시 방출하지 않는다.

### 3.3 예

입력:

```html
<div>대<span>표</span>자 홍길동<p>환율</p>은<b>행</b>장 김철수</div>
```

| owner_path | segment_index | raw run |
| --- | ---: | --- |
| `[0]` | 0 | `대표자 홍길동` |
| `[0,3]` | 0 | `환율` |
| `[0]` | 1 | `은행장 김철수` |

루트에는 방출할 텍스트가 없다. 부모 `div`의 두 run은 같은 구간의 중복이 아니라 자식 B 전후의 서로 다른 구간이다.

Fragment:

```html
대<span>표</span>자 홍길동
```

결과는 `([], 0)` 소유의 `대표자 홍길동` 한 run이다.

**이유:** 가장 가까운 블록 귀속만으로는 부족하다. 같은 부모에 귀속돼도 자식 블록 진입·복귀를 사이에 둔 조각은 분리해야 한다.

**알면서 남기는 한계:**

```html
<div>대</div><div>표자 홍길동</div>
```

```html
<div>대<p></p>표자 홍길동</div>
```

위 입력은 지원 구조이며 직함 후보가 0건이다. 블록 경계를 넘지 않는 정책의 **미탐지**다. 구조 거부나 fail-closed로 표현하지 않는다. CSS가 인라인처럼 보여도 동일하다.

## 4. `br`, 정규화와 직함 문법

### 4.1 줄바꿈과 정규화

`br`은 raw run에 **U+000A LF 하나**를 넣는다. Run 경계가 아니다. 연속 br은 같은 수의 LF다. `wbr`은 문자 0개다.

정규화 함수 N:

```text
전체 문자열 NFKC → ASCII A-Z만 a-z로 변환
```

원문과 저장 바이트는 변경하지 않는다. Unicode 전역 casefold나 `re.IGNORECASE`의 추가 Unicode 동치에 의존하지 않는다.

앞뒤 strip·공백 삭제·연속 공백의 실제 축약은 하지 않는다. v2의 모호한 “공백 접기”는 다음 문법으로 대체한다.

W는 다음 코드포인트 한 글자다.

```text
[\x09-\x0D\x20\x85\xA0\u1680\u2000-\u200A\u2028\u2029\u202F\u205F\u3000]
```

- `W*`: 위 공백 0개 이상.
- `W+`: 위 공백 1개 이상.
- LF를 포함하므로 직함 내부 줄바꿈을 허용한다.
- Python `\s`와 이 집합이 같다고 가정하지 않는다.
- U+200B, U+200D, U+FEFF, soft hyphen은 W가 아니다.
- 임의의 보이지 않는 문자 제거를 하지 않는다.

**이유:** br을 빈 문자열로 만들면 영어 단어 경계가 사라진다. hard boundary로 만들면 직함 내부 줄바꿈을 놓친다.

**한계:** 여러 줄의 별개 문구가 직함으로 결합되는 오탐은 가능하다. W 밖의 제로폭 문자로 갈라진 직함은 놓칠 수 있다.

### 4.2 닫힌 직함 목록

| 가족 | canonical token |
| --- | --- |
| 한국어 | `대표자`, `대표이사`, `대표집행임원`, `은행장`, `행장`, `공동대표`, `각자대표`, `공동대표이사`, `각자대표이사` |
| 영어 | `ceo`, `chief executive`, `chief executive officer` |

한국어 토큰은 완성형 음절 사이마다 `W*`를 허용한다. 앞뒤 단어 경계 조건은 두지 않는다.

예:

```text
대표이사 = 대 W* 표 W* 이 W* 사
```

영어 단어 `chief`, `executive`, `officer`는 ASCII 글자 사이마다 `W*`를 허용한다. 단어 사이는 S다.

```text
H = U+002D 또는 U+2010
S = W+ 또는 W* H W*
```

U+2011은 NFKC 후 U+2010이므로 허용된다. 구분자 없는 `ChiefExecutiveOfficer`는 지원하지 않는다. EN DASH·EM DASH는 H가 아니다.

`ceo`는 다음 세 계열을 같은 canonical token으로 취급한다.

1. `c W* e W* o`
2. `c W* "." W* e W* "." W* o` 및 선택적인 `W* "."`
3. `c W* H W* e W* H W* o`

2번의 끝 선택 부분은 점이 있을 때만 소비한다. 뒤 공백만 소비하지 않는다. 점·하이픈 혼합 약어형은 지원하지 않는다.

모든 영어 토큰 바깥에 다음 경계를 적용한다.

```text
(?<![a-z]) ... (?![a-z])
```

`\b`를 쓰지 않는다.

- `CEO홍길동`: 후보.
- `ABOUTCEO홍길동`: 해당 문자열 관측에서는 후보 없음.
- `CEOLOGY`: 후보 없음.

각 문자열의 모든 시작 위치에서 가능한 후보를 수집한다. 정규식 대안 선언 순서나 비중첩 `finditer`만으로 최장 일치를 대신하지 않는다. 최종 선택은 §6에서 수행한다.

단독 `대표`, `President`, `Chairman`, 다른 언어 직함과 이름만 나온 문장은 범위 밖이다.

**이유:** 이름 모양·이름 위치와 무관하게 직함 자체를 찾고, 동의어 추정을 정책 밖에 숨기지 않는다.

**한계:** `행장 인사말`·`대표자 변경`·한국어 부분 문자열도 후보가 된다. 목록 밖 직함·미지원 구분자는 미탐지할 수 있다.

### 4.3 NFKC와 node/run 좌표

Run 조각은 각 일반 텍스트 노드 전체와 각 br의 LF다. `wbr/img`는 길이 0인 이벤트다.

각 run에서 다음이 완전히 같아야 한다.

```text
N(raw run 전체)
=
각 조각에 N을 적용한 결과의 순서대로 연결
```

다르면 `d1_normalization_boundary_unsupported`로 전체 검사를 거부한다. 후보가 없더라도 이 검사를 생략하지 않는다.

같으면 정규화된 조각 길이의 누적합으로 각 노드의 run 내 시작 좌표를 정한다. 노드 관측의 `[start,end)`에 이 값을 더해 run 좌표로 옮긴다.

한 노드 안의 NFKC 길이 변화는 허용한다. 정규화 좌표를 raw byte offset이라고 주장하지 않는다.

**이유:** NFKC는 연결에 대해 항상 분배되지 않는다. 원문 길이나 노드별 정규화 결과를 무조건 사용하면 병합 위치가 틀어진다.

**알면서 남기는 한계:**

```html
<p>대표자 홍길동</p>
```

한 노드 안의 자모는 `대표자`로 정규화돼 탐지된다.

```html
<p><span>ᄃ</span><b>ᅢ</b>표자 홍길동</p>
```

위 입력은 노드 경계를 넘는 합성이 필요해 거부한다. 유효한 HTML을 지원하지 못하는 비용이며 0건으로 처리하지 않는다.

## 5. Node/run 관측

각 정규화 run 전체와 그 안의 각 정규화 텍스트 노드를 각각 검사한다. br만으로 node 관측을 만들지 않는다.

HTML 텍스트 관측은 다음 정보를 가진다.

- canonical token
- 관측 출처 `node` 또는 `run`
- `(owner_path, segment_index)`
- 해당 run의 정규화 `[start,end)`
- node 관측이면 `node_path`와 노드 내부 정규화 `[start,end)`

Node 관측의 영어 경계는 노드에서 독립적으로 판정한다. Run 경계로 재검사해 취소하지 않는다.

```html
<p><span>ABOUT</span><b>CEO홍길동</b></p>
```

Run `ABOUTCEO홍길동`에는 후보가 없지만, b의 노드에는 `ceo`가 있다. 이 후보는 run 좌표 `[5,8)`로 옮겨 살아남는다.

**이유:** Run은 태그로 갈린 직함을 찾고, node는 인접 텍스트 결합으로 사라진 경계를 보완한다.

**한계:** 단어 중간에 인라인 태그가 있으면 부분 문자열을 독립 직함으로 보는 오탐이 생길 수 있다. Node/run 어느 쪽에도 목록상 직함이 없으면 이름을 알아내지 못한다.

## 6. 중복 제거·최장 선택·승인 식별자

### 6.1 정확한 관측 중복

HTML 텍스트의 병합 키:

```text
(run 식별자, normalized start, normalized end, canonical token)
```

`node/run` 출처는 키에 넣지 않는다. 같은 키는 한 관측으로 합치고 출처 집합만 메모리에 남긴다.

같은 텍스트라도 다른 run·다른 위치이면 합치지 않는다.

속성 scalar 식별자:

```text
(element_path, attribute_name, name/value 구분, list_index 또는 null)
```

Metadata scalar 식별자는 §6.3의 typed field path다. 서로 다른 scalar는 값이 같아도 합치지 않는다.

### 6.2 최장 일치 한 건의 범위

정확 중복 병합 후, **하나의 run 또는 하나의 scalar 안에서만** 통합 후보에 다음 leftmost-longest를 적용한다.

1. 남은 후보의 가장 작은 start를 선택한다.
2. 같은 start 중 end가 가장 큰 후보를 선택한다.
3. 동일 구간에 다른 canonical token이 남는 동률은 §4.2 표의 위→아래, 왼쪽→오른쪽 순서로 선택한다.
4. 선택 구간과 한 글자라도 겹치는 다른 후보를 제거한다.
5. 겹치지 않는 후보에 반복한다.

한 구간의 end와 다음 구간의 start가 같은 경우는 겹치지 않는다. 겹침의 전이적 연결 성분 전체를 하나로 합치지 않는다.

예:

| 후보 | 최종 결과 |
| --- | --- |
| `공동대표이사` 및 내부 `공동대표`·`대표이사` | 1건 |
| `은행장` 및 내부 `행장` | 1건 |
| 같은 노드의 `대표자 홍길동 대표자 김철수` | 2건 |
| 서로 다른 li의 같은 직함 | 각각 1건 |
| 같은 문구의 HTML 출현과 metadata 출현 | 각각 별도 건 |

```html
<p><span>공동</span><b>대표이사</b> 홍길동</p>
```

Node 후보 `대표이사`와 run의 긴 후보를 통합한 뒤 `공동대표이사` 1건으로 선택한다.

**이유:** 한 출현의 중첩 표현과 관측 중복을 없애되, 다른 출현에 승인을 재사용하지 못하게 한다.

**한계:** 이는 직함 출현 수이지 사람 수가 아니다. 동일인이 여러 위치에 있으면 각각 검토한다.

### 6.3 Metadata 경로와 필드 내 출현

경로는 타입을 보존한 배열이다.

```text
["recorded_extraction","events",0,"labels","item_text"]

["recorded_extraction","exception","args",1,0]
```

- 객체 키: 문자열.
- 배열 인덱스: 0 기반 정수.
- `"0"`과 `0`은 다르다.
- 키에 점·대괄호·슬래시가 있어도 의미가 바뀌지 않는다.
- 최상위 metadata 객체가 기준이다. 가짜 `"metadata"` 성분을 추가하지 않는다.

위치는 **N을 적용한 필드 문자열의 Unicode code point 기준 0 기반 `[start,end)`**다. Raw JSON 바이트나 escape 길이가 아니다.

Leaf별 최종 후보를 start 순서로 정렬한 뒤:

- `field_occurrence`: 1부터.
- `field_count`: 그 필드의 전체 최종 D1 건수.

Token별 순번이 아니라 필드의 모든 D1 출현을 합친 순번이다.

`대표자 홍길동 대표자 김철수`는:

| 구간 | field_occurrence | field_count |
| --- | ---: | ---: |
| `[0,3)` | 1 | 2 |
| `[8,11)` | 2 | 2 |

같은 값이 `row_text`에도 있으면 다른 필드 경로의 두 건이다.

**이유:** 일시적인 dict 열거 번호나 중첩 경로를 생략한 진단 문자열은 승인 위치가 될 수 없다.

**한계:** 서로 다른 필드 사이로 갈린 직함은 탐지하지 않는다. 이를 막기 위해 관련 없는 필드를 연결하지 않는다.

### 6.4 순번·건수 확정 시점

다음이 모두 성공한 뒤에만 승인용 순번과 건수를 확정한다.

```text
구조 검사
→ 정규화 대응 검사
→ 모든 관측 생성
→ 정확 중복 병합
→ 최장 선택
→ 최종 정렬
→ 순번·건수 부여
```

순회 중 임시 번호, node/run별 건수, 첫 후보 발견 후 단락 평가를 사용하지 않는다.

최종 정렬:

1. **HTML 텍스트:** run 방출 순서 → start → end → canonical token.
2. **HTML 속성:** element DOM 선행 순서 → 속성 이름 사전순 → name/value 순 → 목록 수치 인덱스 → start.
3. **Metadata:** typed field path 사전순 → start.

경로 성분 비교는 문자열을 정수보다 먼저 두고, 문자열은 Unicode code point 사전순, 정수는 수치순으로 비교한다. 공통 접두부가 같으면 짧은 경로가 먼저다.

승인 대조 필드:

- 공통 `rule_id = d1_role_context`
- source 종류
- source별 위치 식별자
- canonical token
- 정규화 `[start,end)`
- `occurrence_index`: 전체 최종 목록의 1 기반 순번
- `total_count`: 모든 출처의 최종 건수
- Metadata에는 추가로 `field_occurrence`, `field_count`

Source별 위치 필드를 닫힌 variant로 검증한다. 다른 source의 필드를 섞거나 임의 필드를 추가하지 않는다.

Node/run 출처 집합은 진단용 메모리 정보다. 승인 항목을 두 개 만들지 않는다. Canonical token은 정책 상수이며 실제 일치 문구나 주변 문장을 복사한 값이 아니다.

A층은 동일 파일·동일 정책에서 재산출한 목록과 승인 항목을 정확히 대조한다. 누락·중복·여분·위치·토큰·순번·건수 불일치를 거부한다.

**한계:** 이름만 바뀌면 위치·순번은 그대로일 수 있다. 바이트 변경에 따른 재검토는 두 파일 SHA-256이 강제한다.

## 7. 저장 전 치환 대응

### 7.1 이번 실행의 증거

성공한 좁은 치환마다 메모리에 다음을 보관한다.

- 치환 후 단일 노드 identity.
- 구조 경로.
- 보존한 정확한 라벨.
- 노드 안의 정규화 라벨 `[start,end)`.

삭제한 성명 값은 기존 추출 기록 잔존 검사에만 메모리에서 사용한다. 증거 파일에 복사하지 않는다.

저장 허용에는 다음 조건이 모두 필요하다.

1. 최종 HTML 출현 전체가 성공 작업의 **한 노드에 있는 보존 라벨 범위 안**에 있다.
2. 지원 li·검토된 공시 영역·정확한 라벨·유일한 값 경계가 실제로 확인됐다.
3. 이번 실행에서 값이 `[성명삭제]`로 바뀌었다.
4. 이웃 텍스트와 결합해 만든 다른 직함이 아니다.
5. 같은 직함·같은 순번이라는 이유로 다른 위치의 성공 작업을 대입하지 않았다.

라벨·구분자·치환 값 경계에도 §4.3의 정규화 연결 일치 검사를 적용한다. 경계가 증명되지 않으면 거부한다.

속성·metadata 후보는 HTML 노드 치환에 대응하지 않으므로 저장 전에 거부한다. 무해한 문맥이어도 캡처 단계에서 승인 파일로 우회하지 않는다.

### 7.2 재파싱 후 대응

직렬화 후에는 Python 객체 identity가 사라진다.

성공 작업을 치환 후 구조 경로·조상 태그 경로·단일 li 조건·치환 후 노드 전체 문자열·라벨 범위에 결속하고, 재파싱 결과의 **정확히 그 경로**에서 재검증한다. 비교 문자열은 메모리에만 둔다.

경로 이동·노드 분할/병합·조건 불일치는 `d1_replacement_correspondence`로 거부한다. 다른 위치에서 같은 문자열을 검색해 증거를 옮기지 않는다.

저장 바이트의 재파싱 결과에서 D1 목록 전체를 다시 완성한다. 새 후보가 생기거나 대응하지 않는 후보가 하나라도 있으면 발행하지 않는다.

**이유:** A층이 검사하는 대상은 저장 바이트다. 자리표시자·직함·순번만으로 이번 실행의 치환을 증명할 수 없다.

**한계:** 이 대응은 실행 내 저장 관문이다. A층의 해시 검사가 생성 이력 전체를 증명하는 것은 아니다.

### 7.3 정책 digest

정책 descriptor는 다음을 결속한다.

- `policy_spec_sha256`: 본 명세의 정확한 UTF-8 바이트 SHA-256.
- `implementation_files`: 현재 D1 구현에 관여하는 명시적 파일 경로→SHA-256 manifest.
- `runtime`: Python 구현·전체 버전, Unicode 데이터 버전, bs4 버전, 파서 이름, 실제 `html.parser` 모듈 SHA-256.

Descriptor의 결정적 JSON 직렬화는 키 정렬, UTF-8, `ensure_ascii=false`, 공백 없는 구분자, NaN 금지로 고정한다. 그 바이트 SHA-256이 정책 digest다.

명세에 자기 digest를 넣지 않는다. 승인 기록이 외부에서 계산한 값을 보유한다. 실제 구현 파일을 임의로 manifest에서 생략하지 않는다.

정책·목록·정규화·경계·병합·순서·검사 환경 변경은 기존 승인을 무효화한다. 캡처 당시 `metadata.parser`·`extraction_contract`는 현재 정책 digest를 대신하지 않는다.

### 8.4 정규화·정규식 실측

Br 사례의 regex 입력에는 명세의 LF를 명시적으로 넣었다.

| 입력 HTML 그대로 | 실측 |
| --- | --- |
| `<p>대<br>표<br>자 홍길동</p>` | `대\n표\n자` 후보 `[0,5)` |
| `<p>Chief<br>Executive<br>Officer 홍길동</p>` | 긴 후보 `[0,23)` |
| `<p>ChiefExecutiveOfficer 홍길동</p>` | 후보 없음 |
| `<p>Chief-Executive-Officer 홍길동</p>` | 긴 후보 `[0,23)` |
| `<p>Chief&#x2011;Executive&#x2011;Officer 홍길동</p>` | U+2011→U+2010; 긴 후보 `[0,23)` |
| `<p>Chief&#x2014;Executive 홍길동</p>` | 후보 없음 |
| `<p>CEO홍길동</p>` | ceo `[0,3)` |
| `<p>ABOUTCEO홍길동</p>` | 후보 없음 |
| `<p>CEOLOGY</p>` | 후보 없음 |
| `<p>ＣＥＯ홍길동</p>` | NFKC 후 ceo `[0,3)` |
| `<p>C E O 홍길동</p>` | ceo `[0,5)` |
| `<p>C.E.O. 홍길동</p>` | ceo `[0,6)` |
| `<p>C-E-O 홍길동</p>` | ceo `[0,5)` |
| `<p>대&#x200B;표자 홍길동</p>` | U+200B 잔존, 후보 없음 |
| `<p>대표자 홍길동</p>` | NFKC 후 대표자 `[0,3)` |
| `<p><span>ᄃ</span><b>ᅢ</b>표자 홍길동</p>` | 전체 NFKC=`대표자 홍길동`; 조각별 연결=`대표자 홍길동`; 불일치 |
| `<p><span>Chief </span><b>Executive</b><i> Officer</i> 홍길동</p>` | 전체 정규화와 조각별 연결 일치 |

긴 영어 직함에는 짧은 `chief executive` 후보도 성립할 수 있다. 최종 긴 후보 한 건 선택은 §6의 규범이다. 이 regex 측정만으로 통합 병합 구현이 검증됐다고 주장하지 않는다.

## 9. 독립 구현 검증 조건

다음은 구현 후 수행할 조건이며 이미 통과한 테스트 목록이 아니다.

1. 실측 표를 같은 환경에서 재현하고 규범 기대값과 대조한다.
2. Ruby 가족의 빈·고아·중첩·주석 분할 변이가 모두 구조 거부되는지 확인한다.
3. I 전체를 직함 사이에 넣고, 특수 요소·인라인 내부 B·빈 U를 구별한다.
4. Fragment·wrapper·부모 직접 텍스트·자식 B·복귀 후 텍스트·빈 B·table/td 경계에서 소유·방출 불변식을 검사한다.
5. NFKC 길이 변화·경계 합성·영어 경계·연속 br·제로폭 문자를 “후보”, “검사 불가”, “알려진 0건”으로 구별한다.
6. Node/run 동일 좌표·긴 직함·떨어진 반복·다른 run·속성·metadata 경로를 서로 구별한다.
7. 동일 파일을 두 번 검사하면 목록·순번·건수가 같아야 한다. 내부 dict 순서가 metadata 위치 의미를 바꾸지 않아야 한다.
8. 이름만 바꿔 위치 튜플이 그대로여도 파일 해시로 승인이 무효여야 한다. 후보가 그대로인 정책 변경도 digest로 무효여야 한다.
9. 원래 자리표시자·다른 위치의 성공 치환·추가 출현·metadata 출현·재파싱 대응 실패는 저장 전에 거부돼야 한다.
10. 삭제 대상 성명이 추출 기록에 남으면 양쪽 기록을 변경하지 않고 거부해야 한다.
11. 기존 route의 새 정책 0건 여부는 실제 구현으로 해당 저장 바이트를 재검사한 뒤에만 말한다. 이 문서에서는 기존 fixture의 새 정책 통과나 캡처 성공률을 측정하지 않았다.

잔여 미탐지 범위는 블록/필드 경계를 가르는 직함, 목록 밖 직함, 직함 없는 성명, 이미지·CSS·동적 내용, 미지원 구분·인코딩이다. 사람 검토는 계속 필요하다. 이 미탐지와 미지원 구조의 거부를 혼동해 “모든 이름에 대해 fail-closed”라고 기록하지 않는다.

# C1b D1 탐지 정책 v1 — 개정 1

작성: Claude(초안)·Codex(검토) / 2026-09-21
기준 문서: 같은 폴더의 `d1_detection_policy_v1.txt`, sha256 `47d090a63997116d8df9af80b3a04a3e99a5a62c487aaba34236d1897e273635`.
v1 의 바이트는 바꾸지 않는다. v1 과 이 개정이 충돌하면 **이 개정이 우선**한다. 조항은 번호 순서로 적용한다.
이 개정은 자기 digest 를 담지 않는다. 개정 파일의 실제 바이트 SHA-256 이 §A3 의 `policy_amendments` 에 들어간다.

## A1. §6.1 속성 위치 — 이름 대신 번호 (슬라이스 3 에서 이미 시행 중인 정정을 명세로 옮김)

속성 발견의 위치는 속성 **이름**이 아니라 `attribute_index` 로 가리킨다. `attribute_index` 는 그 요소에서 파싱된 속성 이름 **전부**를
code point 순으로 정렬했을 때의 0 부터 시작하는 번호다. 정렬은 정규화·탐지 전에 하고, 직함이 없는 이름도 번호를 차지한다.

**이유:** 속성 이름은 페이지 텍스트다. `data-대표자홍길동` 처럼 성명이 이름에 그대로 들어올 수 있어(실측), 이름을 위치로 복사하면 누출이다.

## A2. §1.3 "환경 불일치" 의 구분

§1.3 의 "환경 불일치" 를 다음 둘로 나눈다.

1. **필수 환경 조건 불충족 — 검사 불가.** §A3 의 검토 환경 서술자를 만들 수 없는 경우(요구 모듈의 파일이 없거나 읽을 수 없음, 버전을
   얻을 수 없음 — 속성이 없거나, 얻는 중 예외가 나거나, 비어 있지 않은 문자열이 아님)와, 파서가 `html.parser` 가 아닌 경우.
   0건으로 반환하지 않는다. 알려진 값·빈 값으로 대신하지 않는다.
2. **승인 기록의 검토 환경과 현재 환경의 차이 — 검사 불가가 아니다.** A층은 현재 환경에서 모든 검사를 처음부터 다시 수행하고
   §A3 의 조건으로 대조한다. 차이 자체로 거부하지도, 차이가 없다는 이유로 재산출을 생략하지도 않는다.

## A3. §7.3 정책 digest — 정책과 검토 환경의 분리

v1 §7.3 은 runtime 을 descriptor 에 넣어 digest 에 결속했다. CI 는 Python 패치 버전이 움직이고(2026-09-21 CI 실측 CPython 3.13.15,
검토 환경 Anaconda CPython 3.13.5), 모듈 바이트는 배포판마다 다를 수 있어, 그 결속으로는 검토 환경에서 쓴 승인이 CI 에서 대조될 수 없다.
그래서 둘을 나눈다.

**정책 descriptor** (닫힌 schema, 이것만 digest 입력):

- `policy_spec_sha256`: v1 파일의 실제 바이트 SHA-256.
- `policy_amendments`: 적용 순서대로의 개정 파일 실제 바이트 SHA-256 목록.
- `implementation_files`: D1 구현에 관여하는 명시적 리포 상대 경로 → 실제 바이트 SHA-256.

명세·개정·구현 파일은 모두 **리포 안의 정해진 상대 경로**에서, 실행 중인 checkout 을 기준으로(CWD 무관) 바이트 그대로 읽는다.
**매 호출 현재 파일 바이트를 읽으며 이전 결과로 대신하지 않는다.**
개행·BOM 등 어떤 변환도 하지 않는다 — 다른 checkout 에서 개행이 변환되면 digest 가 달라지며, 이는 의도된 거부다.
파일을 읽지 못하면 검사 불가다. 기대 SHA 상수를 둘 수 있으나 실제 읽기를 대신하지 않는다.

정책 digest = 정책 descriptor 를 v1 §7.3 과 같은 결정적 JSON(키 정렬, UTF-8, `ensure_ascii=false`, 공백 없는 구분자, NaN 금지)으로
직렬화한 바이트의 SHA-256(소문자 64자리 hex).

**검토 환경 서술자** (digest 입력 아님, 승인 기록에 검토 환경으로 기록):
`python_implementation`, `python_version`(빌드 문자열 제외), `unicode_version`, `bs4_version`, `soupsieve_version`, `parser`(= `html.parser`),
`html_parser_sha256`, `markupbase_sha256`(`html.parser.HTMLParser` 가 상속하는 `_markupbase` 모듈). 모듈 해시는 **그 모듈 파일의
바이트 차이만** 포착한다. 런타임 전체의 신원을 증명하지 않는다. 모듈 경로는 읽기에만 쓰고 서술자에 넣지 않는다.

**A층 승인 조건** (전부 필요):

1. 두 최종 파일의 SHA-256 이 승인 기록과 일치한다.
2. 현재 정책 digest 가 승인 기록의 정책 digest 와 일치한다.
3. 현재 환경에서 모든 검사가 완료된다(검사 불가 없음). 검토 환경과 같아도 재산출을 생략하지 않는다.
4. 재산출한 발견 목록 전체가 승인 항목과 **자료형·순서까지** 정확히 같다.

**한계:** 재산출 목록의 일치는 그 저장 바이트에 대한 D1 승인 식별자의 일치를 보장한다. 파싱된 DOM 이나 직함 주변 문맥 전체가 검토
환경과 같다는 것을 증명하지 않는다 — 발견 기록은 문맥을 담지 않으므로, 파서가 문맥만 다르게 만들면 목록은 같을 수 있다.

v1 §7.3 의 "정책·목록·정규화·경계·병합·순서·검사 환경 변경은 기존 승인을 무효화한다" 는 다음으로 바꾼다:
**정책·목록·정규화·경계·병합·순서 또는 명세·개정·구현 파일의 변경은 정책 digest 를 바꿔 기존 승인을 무효화한다. 검사 환경의
변경은 승인을 무효화하지 않고, 위 조건 3·4 의 재산출·정확 대조로 대신한다.**

`implementation_files` 의 범위는 계약이 정한 D1 진입 모듈과 패키지 `__init__.py` **둘 다를 시작점으로** 패키지 안 import 를 따라간 폐포와
정책 digest 모듈 자신이다(`__init__.py` 는 import 때 실행되므로, 그 파일의 해시만으로는 그것이 끌어오는 파일의 변경을
결속하지 못한다). 동적 import 는 허용하지 않는다(쓰려면 manifest 와 계약을 다시 검토한다). 캡처·A층 배선(슬라이스 5)으로 D1 호출과
관문 순서를 가진 파일이 생기면 그 파일도 포함 여부를 다시 판단한다 — 호출 제거·순서 변경도 승인 정책의 실효성을 바꾸기 때문이다.
